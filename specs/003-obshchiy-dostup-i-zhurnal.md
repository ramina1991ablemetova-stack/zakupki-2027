# Общий доступ, авторизация и журнал изменений

## Для кого и зачем

Для сотрудников, совместно планирующих закупки, и администратора, которому нужна история изменений. Существующие оформление и денежные расчёты сохраняются.

## Что должно быть

- В каждом разделе есть кнопка «Добавить закупку»; количество закупок не ограничено искусственно.
- При входе доступны режимы «Просмотр» и «Редактирование». Просмотр не позволяет изменять данные.
- Для редактирования необходимы вход через Google и проверка указанного пользователем кода доступа на сервере. После успешной проверки сервер предоставляет право редактирования; клиентская проверка сама по себе права не предоставляет.
- Общие данные хранятся в Firestore, а изменения отображаются у других пользователей. Требуется определить порядок переноса существующих локальных данных, чтобы не потерять и не продублировать записи.
- Если абсолютное отклонение от плана за месяц строго превышает 10% плана, ячейка отклонения выделяется красным. При нулевом плане ненулевой факт также выделяется, а нулевой факт — нет.
- Для каждого сохранённого изменения журнал содержит серверные дату и время, имя и электронную почту пользователя, наименование закупки, поле, старое и новое значение. Записи журнала создаются серверной доверенной частью вместе с изменением данных и доступны только администратору.
- Права просмотра, редактирования и доступа к журналу обеспечиваются серверной проверкой и правилами Firestore, в том числе при прямом обращении к базе.

## Примеры

- Вымышленный сотрудник изменил план закупки «Бумага» за январь с 100 000,00 на 200 000,00 ₸: новый итог появляется у другого пользователя, а журнал фиксирует оба значения и автора.
- Пользователь в режиме просмотра может видеть закупки, но не может изменить их через интерфейс или запрос к базе.
- Пользователь с правом редактирования без прав администратора не может прочитать журнал.

## Ограничения

- Используются Firebase Authentication и Firestore; проверка кода выполняется на сервере. Код доступа не помещается в общедоступный JavaScript или репозиторий; серверный секрет настраивается отдельно.
- Серверная часть и правила доступа необходимы для общей базы и защищённого журнала. Публикация и настройка облачного проекта выполняются только с разрешения пользователя.
- Существующие значения в localStorage необходимо сохранить до согласования миграции. Суммы в тенге без НДС рассчитываются с точностью до двух знаков без ошибок округления.
- Доступны экраны от 375 px, кнопки и поля не менее 44 px; интерфейс на русском языке. Примеры содержат только вымышленные данные.
- Требуются настройки Firebase-проекта и определение администратора. Необходимо уточнить, должен ли режим просмотра быть общедоступным или требовать входа.

## Готово, когда

- В обоих разделах добавляются и сохраняются несколько закупок без искусственного ограничения.
- Режим просмотра не позволяет записывать данные; редактирование доступно только после Google-входа и успешной серверной проверки кода.
- Проверено, что неверный код и прямые неавторизованные запросы не дают права записи и чтения журнала.
- Изменение появляется у второго пользователя, сохраняется после обновления и сопровождается корректной записью журнала, доступной только администратору.
- Проверены существующие расчёты, сохранность прежних данных и поведение при ошибке сети; README содержит инструкции по настройке и запуску.
