# Ввод закупок в сетевой график

## Для кого и зачем

Для сотрудника, планирующего закупки: чтобы вводить и изменять сведения непосредственно в таблице сетевого графика и разделять закупки по очередности.

## Что должно быть

- Главная страница представляет сетевой график как редактируемую таблицу, похожую на таблицу Excel. Отдельной формы «Новая закупка» нет: пользователь вводит и редактирует данные непосредственно в ячейках.
- Таблица содержит два раздела: «Первоочередные закупки» и «Непервоочередные закупки». В каждом разделе предусмотрены пустые строки для заполнения; введённые данные относятся к тому разделу, в котором находится строка.
- Столбцы таблицы: «Наименование закупки», «Номер договора», «Поставщик / примечание», «Ответственный», «Сумма договора», «Отклонение от суммы договора», «Материал SAP», «Вид затрат», «Статус закупки».
- Номер договора, поставщик / примечание, сумма договора и отклонение могут оставаться пустыми до заключения договора. Частично заполненные строки сохраняются, чтобы пользователь мог вернуться к ним позже.
- Изменения автоматически сохраняются в localStorage и восстанавливаются после обновления страницы вместе с принадлежностью строк к разделам. Ошибки сохранения сообщаются пользователю; введённые данные остаются доступными для исправления или повторной попытки.
- Таблица поддерживает горизонтальную прокрутку, чтобы все столбцы были доступны на узком экране.
- Помесячный план, факт и отклонение с января по декабрь относятся ко второй функции и в эту спецификацию не входят.

## Примеры

- В пустой строке раздела «Первоочередные закупки» пользователь вводит «Бумага для офиса», «Айдана Садыкова», вид затрат «Материалы» и статус «Планируется», оставляя договорные поля пустыми. После обновления страницы введённые данные остаются в том же разделе.
- В разделе «Непервоочередные закупки» пользователь вводит вымышленную закупку «Учебное оборудование», а затем в той же строке дополняет номер договора «Д-002», поставщика «ТОО Учебный пример» и сумму договора 125 000,55 ₸ без НДС. Изменения сохраняются автоматически.
- Если денежное значение некорректно, пользователь видит понятное сообщение и может исправить введённое значение; некорректное значение не выдаётся за корректную сумму.

## Ограничения

- Использовать HTML, CSS и JavaScript; интерфейс — на русском языке, данные хранить в localStorage.
- Суммы указывать в тенге без НДС с точностью до двух знаков после запятой; исключить ошибки округления и NaN.
- Поддерживать экраны шириной от 375 px; кнопки и поля должны быть не менее 44 px. Все столбцы доступны через горизонтальную прокрутку.
- Использовать только вымышленные примеры. Не изменять работающие функции без согласования.
- Правила ввода отрицательного отклонения, поведение при некорректных денежных значениях и способ предоставления дополнительных пустых строк необходимо уточнить до реализации.

## Готово, когда

- На главной странице есть редактируемая таблица с двумя указанными разделами, девятью столбцами и пустыми строками в каждом разделе; отдельной формы добавления нет.
- Пользователь может вводить и изменять данные непосредственно в ячейках обоих разделов, в том числе сохранять частично заполненные строки с пустыми договорными полями.
- После F5 введённые и изменённые сведения восстанавливаются в соответствующих разделах.
- Сумма 125 000,55 ₸ без НДС отображается с двумя знаками после запятой; некорректное денежное значение сопровождается понятным сообщением.
- На экране шириной 375 px доступны все столбцы с помощью горизонтальной прокрутки, а кнопки и поля соответствуют минимальному размеру.
- Помесячные план, факт и отклонение рассматриваются во второй функции.
